# Phase 4 Plan: Firebase Auth and Firestore Adapter

## Steps

1. Add Firebase Flutter dependencies and a Firestore-backed repository adapter without changing the default local demo entry point.
2. Tighten Firestore rules so clinician sleep reads require trusted clinician auth and accepted deterministic links.
3. Add repo-local Firestore emulator rules tests that cover all Firebase collections in the contract.
4. Keep Analytics, Crashlytics, and telemetry absent.
5. Run `npm run test:firestore-rules`, `flutter analyze`, `flutter test`, `flutter build web`, and `flutter build web --base-href /nguyenindoubt-app/`.

## Acceptance checks

- Screens and widgets do not import Firebase packages directly.
- Firebase adapter implements repository interfaces.
- The public app still builds in local demo mode without Firebase initialization.
- Firestore rules deny clinician journal reads regardless of accepted link status.
- Firestore rules deny pending, revoked, missing, malformed, and unclaimed clinician sleep reads.
- Firestore emulator tests pass.
- No Analytics or Crashlytics dependencies are present.
