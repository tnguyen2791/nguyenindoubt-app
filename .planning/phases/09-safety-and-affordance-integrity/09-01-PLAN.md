<objective>
Make the Safety screen's crisis controls take real action in a single tap: launch `tel:988` / `sms:988` / `tel:911` directly through `url_launcher`, instead of opening an explanatory `AlertDialog` (the "affordance lie" a button labeled with an action that only shows a paragraph). Keep the existing educational text as calm inline secondary copy, guard every launch with `canLaunchUrl`, and degrade gracefully (selectable number) when no handler exists.

Purpose: In a crisis, latency is dangerous — SAFE-01 removes the extra tap-and-read and makes the control do what it says, while staying educational and explicitly non-monitoring (no in-app dispatch, no auto-dial, no "we contacted…" language).
Output: A thin injectable `CrisisLauncher` seam, a rewired `SafetyScreen`, and tests that verify the requested URI behind the seam without dialing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app -> OS dialer/SMS | App hands a `tel:`/`sms:` URI to the platform; the OS (not the app) initiates the call/text. |
| user tap -> launch | Launch only fires on explicit user interaction, never on build/auto. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01-A | Tampering | Crisis URI values | low | mitigate | URIs are hardcoded constants (`tel:988`/`sms:988`/`tel:911`); no user/remote input flows into the launched Uri. |
| T-09-01-B | Denial of Service | Launch on web / missing handler | medium | mitigate | `canLaunchUrl` guard + graceful `SelectableText` number fallback so the user can still reach help; never crash. |
| T-09-01-C | Repudiation/Safety | Implying in-app dispatch or auto-dial | high | mitigate | No auto-invoke; launch only on explicit tap; no "we contacted…" language; retain the non-monitoring disclosure (DEMO-05). |
</threat_model>
