Complete the private-journal promise (SAFE-03): give the journal an `EmptyState` when there are no entries, and add per-entry delete gated by a confirmation dialog. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| patient -> journal repository | Only the owning patient may read/write/delete their journal entries (interface guard + Firestore `ownsDoc()`). |
| client delete -> Firestore rule | Client requests a doc delete by id; the server rule authoritatively enforces ownership. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-03-A | Elevation of Privilege | Non-owner deleting a journal entry | high | mitigate | InMemory `_ensurePatientOwnsData` guard + Firestore `ownsDoc()` on delete, proven by rules test (patient allowed; clinician/other denied). |
| T-09-03-B | Tampering | Deleting the wrong / unintended entry | medium | mitigate | Confirmation dialog stating permanent on-device removal before delete; delete targets an exact entry id. |
| T-09-03-C | Information Disclosure | Empty-state copy implying journal is visible to others | medium | mitigate | Empty-state copy is patient-private and never implies anyone else can read it (standing privacy contract). |
| T-09-03-SC | Tampering | Supply chain (test deps) | low | accept | No new npm/pip/cargo installs — `@firebase/rules-unit-testing`/`vitest`/`firebase-tools` already present in package.json devDependencies. |
</threat_model>
